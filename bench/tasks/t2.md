title: readItem must not read files outside the data directory
---
`readItem(dataDir, name)` in `src/store.js` builds the path from `name` without checking it, so `readItem(dir, "../secret")` reads a file outside `dir`. Fix it.

Requirements:
1. A valid `name` matches `^[A-Za-z0-9_-]+$`. Anything else (including an empty string, `..`, names with `/`, `\`, `.` or a NUL character, and non-string values) throws an `Error` whose message starts with `invalid item name`.
2. A valid name whose file does not exist throws an `Error` whose message is exactly `item not found: <name>` (not the raw ENOENT error).
3. A valid name with an existing file keeps returning the parsed JSON, as today.
4. Malformed JSON in an existing file is not hidden: it still throws the parse error.

Deliverable: the fix in `src/store.js` plus tests in `test/store.test.js` (extend the existing file) that cover the cases above.
Check: `npm test` passes.
Out of scope: other files, adding dependencies, changing the function's signature.
